# TECHNICAL DESIGN

## 1. 프레임 파이프라인 (`GameSession._process`)
```
dt = min(delta, 1/30)                 # 긴 프레임에서도 충돌을 건너뛰지 않음
타이머 → 각 SnakeActor.simulate(dt)   # brain.think → movement.step → 경계 → path.push/trim → body.rebuild
→ SnakeSpatialIndex.rebuild          # 이동이 끝난 위치로 1회
→ FoodField.update                   # 흡수 시작/진행/지급, 사체 수명, 보충
→ CombatSystem.resolve → CombatResult # 물기(XP 이동 완료) → 흘린 먹이·시그널 / 삼킴 → 보상·사체·kill·부활 예약
   (이펙트·사운드·흔들림은 MatchFeedback이 시그널을 받아 처리)
→ Leaderboard(0.25s) → 부활 → 보스 연출 → 그리기 순서(0.5s) → 종료 카운트다운
```
일시정지는 `SceneTree.paused`로 처리하고, 화면 컨트롤러와 일시정지·결과 UI는 `PROCESS_MODE_ALWAYS`로 동작한다.

## 2. 뱀 이동과 몸통 추적 (핵심 시스템)

### 머리 (`SnakeMovement`)
- 원하는 방향과의 각도 오차 × `turn_gain` → 목표 각속도(±`turn_rate`로 제한) → 지수 보간(`turn_smoothing`). 급반전 시 즉시 뒤집히지 않고 U자로 돈다.
- 속도도 목표 속도로 지수 보간한다. 회전 속도와 이동 속도를 분리 관리한다.
- 덩치가 커지면 `turn_rate / (r/r0)^0.35`로 선회 반경이 자연스럽게 커진다.

### 궤적 (`SnakePathHistory`)
- 머리가 `0.18r` 이동할 때마다 점 하나와 **누적 거리**를 기록한다 (`PackedVector2Array` + `PackedFloat64Array`).
- `sample_evenly(spacing, count)`: 머리에서 `spacing × i` 떨어진 지점을 **최신 점부터 한 번만 훑어서** 선형 보간으로 구한다. O(점 수 + 구슬 수).
- **트림:** 필요한 길이(현재 길이와 목표 길이 중 큰 값 + 6r)보다 뒤의 점을 64개 단위로 잘라낸다. 메모리는 플레이 시간이 아니라 몸 길이에 비례한다 (Lv99,999에서 374점).
- **꼬리 외삽:** 갑자기 크게 성장해 기록이 몸보다 짧으면, 가장 오래된 진행 방향으로 직선 연장한다 (구슬이 한 점에 쌓이는 문제 방지).
- 스폰 시 몸 길이만큼 직선 궤적을 미리 깔아 몸이 완성된 상태로 등장한다.

### 몸통 (`SnakeBody`)
- **논리 길이와 렌더 구슬 수를 분리:** `count = min(ceil(length / 0.55r), 140)`, `spacing = length / count`. 상한에 닿으면 구슬 수를 줄이는 대신 간격을 넓히므로 **보이는 길이 = 논리 길이**가 항상 유지된다. Lv99,999에서 간격 1.18r < 지름 2r → 여전히 겹친 사슬.
- 같은 `positions/radii` 배열을 렌더링과 충돌이 함께 쓴다. 보이는 곳이 곧 맞는 곳이다.
- 꼬리 테이퍼(마지막 9구슬), 삼킴 혹(가우시안, 최대 6개 동시).
- 구슬별 물리 노드 없음. 뱀 하나 = 노드 4개(Actor, BodyRenderer, Face, Crest).

## 3. 렌더링
- **구슬:** `SnakeBodyRenderer._draw()`에서 꼬리→머리 순으로 `draw_texture_rect`. 같은 텍스처·같은 머티리얼이라 뱀 하나가 배치 1개로 그려진다.
- **스킨 셰이더:** `snake_skin.gdshader`가 HSV에서 Hue만 교체하고 채도·명도에 배율을 곱한다. 드로우별 정보는 버텍스 컬러 채널로 전달한다 (r=밝기 플래시, g=띠 색 선택, b=물림 붉은 틴트, a=알파). Godot 4에서는 fragment의 `COLOR`가 이미 텍스처와 곱해져 있으므로 `vertex()`에서 varying으로 원본을 받는다. 이 버그는 실제 화면 검수에서 발견해 수정했다.
- 구슬은 회전하지 않는다 (광원 일관성). 방향은 `SnakeFaceRenderer`의 눈 배치·동공으로 표현한다.
- 보스 뿔·글로우는 `show_behind_parent` 자식 노드라 몸 뒤에 그려진다.
- 먹이: `FoodField._draw()` 한 번으로 화면 안(+64px)에 있는 것만 그린다.
- 모든 게임 텍스처에 밉맵을 켜서 크게 축소해도 반짝이지 않는다 (구슬 256px → 화면 약 30px).
- 렌더러는 GL Compatibility다. 2D MSAA는 이 렌더러에서 지원되지 않아 설정에서 제거했다 (안티에일리어싱은 텍스처 필터와 `antialiased` 드로잉으로 처리).

## 4. 전투 (`CombatSystem` + `SnakeSpatialIndex`)
- 매 프레임 모든 살아 있는 뱀의 머리와 구슬을 균일 격자 해시(셀 160px)에 넣는다. 핸들 = `slot × 1024 + part` (머리 = 1023).
- 공격자마다 두 단계로 질의한다.
  1. **타격:** 머리 원(그려진 머리의 95%)과 겹치고 **머리 앞쪽 절반(±90°)** 에 있는 부위 중, 공격 가능한(레벨이 엄격히 높음, 쿨다운 끝, 상대 보호 중 아님) 가장 깊은 것. 상대가 보호 중이라 못 친 경우는 `blocked` 시그널로 알린다(→ "SHIELD").
     - 몸통: 목(앞 15%)이면 삼킴, 아니면 `bite_chunk(닿은 구슬, 비율)`
     - 머리: `bite_chunk(0, 물기 비율)` (최대 80%)
     - 남는 레벨이 바닥(Lv1)이면 삼킴
  2. **접촉:** 타격이 없으면 같은 레벨 머리끼리 튕김, 그 밖에 닿은 뱀은 모두 벽(`_is_wall_for`: 밀어내기 + 안쪽 속도 제거). 예외는 보스가 자기보다 낮은 뱀에 닿은 경우(무시 = 통과)와 보호 중인 뱀(질의에서 제외).
- **`SnakeActor._shrink(share)`:** 물어뜯기·머리 물기·자기장 침식·`cut_at`이 모두 이 한 경로를 쓴다. 몸 길이를 비율만큼 줄이고, 레벨을 `SnakeTuning.level_for_length(남은 길이)`로 다시 계산한다(크기 = 힘). 반지름이 새 레벨로 줄어드는 동안 몸이 다시 길어 보이지 않도록 길이 상한을 둔다.
- **보스 약점:** `SnakeActor.is_weak_spot(i)` = 금색 띠이면서 몸 뒤쪽 50% 이후. 보스가 분노 상태(쇼다운)일 때만 플레이어의 타격이 레벨 비교를 건너뛴다.
- 결과(`CombatResult`)는 `CombatConsequences`가 처리(먹이, 보상, 부활, 승리)하고, 연출은 `MatchFeedback`과 HUD가 시그널로 처리한다.

## 4-1. 자기장 (`ZoneSystem` / `ZoneErosion` / `ZoneRenderer`)
- 상태: WAITING(현재 원 유지, 다음 원 공개) → SHRINKING(중심·반지름 선형 보간) → 다음 단계 … → DONE. 쇼다운이 `start_final()`로 최종 단계를 바로 시작한다.
- 다음 원은 `현재 중심 + 무작위 방향 × (현재 반지름 − 다음 반지름) × center_shift`에 놓이고, 경기장 벽을 넘지 않게 고정한다.
- 침식은 0.5초 틱마다 `erosion_per_sec × 틱` 비율로 `erode()`를 호출한다. 남는 레벨이 바닥이면 사망(킬러 없음).
- 연동: 먹이 생성(구역 안, 넓이 비례), 부활 위치(다음 원 안), AI(구역 밖으로 나가는 방향은 위험도 상승, 밖에 있으면 다음 원 중심으로 복귀), 보스 순찰(구역 중심부), HUD(구역 패널, 미니맵).
- 렌더링: 구역 밖 장막은 굵은 원호 한 개, 경계선과 다음 원 점선은 화면 픽셀 기준 두께. 점선 개수는 화면상 둘레에 맞추고, 화면 안의 점선만 그린다.

## 5. AI
- 판단 주기는 0.14~0.20초 ± 25%로 개체마다 엇갈리게 한다. 판단 때 인지(`AIPerception`)와 위험도 맵(`AISteering.update_danger`)을 갱신하고, 매 프레임 상태가 원하는 방향을 위험도 맵에 통과시켜 최종 방향을 정한다(`AISteering.choose`).
- 위험도 맵: 16방향 × (예측된 위협 입과의 정렬도, 2.5R·5.5R 지점 탐침에 걸리는 몸통/벽). 위험도 0.85 이상인 방향은 다른 길이 없을 때만 쓴다.
- 비용: 판단당 시야 질의 1회 + 먹이 질의 1회 + 탐침 32개 × 장애물(최대 48개).

## 6. 먹이 (`FoodStore` / `FoodField` / `FoodRenderer`)
- 데이터는 노드 없는 패킹 배열 풀(빈 슬롯 재사용)과 공간 해시(셀 96px)로 관리한다. 동작(생성·흡수·사체·AI 질의)과 드로잉은 별도 클래스다.
- 상태: FREE / IDLE / ABSORBING. 흡수 중에는 해시에서 빠져 중복 획득이 없다. 축소된 경기장 밖의 먹이는 정리한다.
- 드로잉은 화면 안(+64px)만 하고, 반지름이 **화면 기준 최소 2.6px** 아래로 내려가지 않게 해서 크게 줌아웃해도 보인다.

## 7. 성능 측정
| 시나리오 | 결과 |
|---|---|
| 일반 경기 시뮬레이션 1스텝 (12마리, 먹이 ~1,500, 컨텍스트 스티어링) | **2.2~2.7 ms** |
| 플레이어 Lv99,999 + AI Lv800 | **4.6 ms** |
| 90초 전체 경기 평균 (밸런스 프로브) | 2.6~3.4 ms |
| 창 모드 실제 FPS (1280×720, vsync) | 게임플레이 **71~120 FPS** (고레벨·다수 뱀 + 자기장 장막 장면이 최저) |

## 8. 오류 처리
- 리소스 누락: `AssetCatalog`가 `push_error`로 키·경로를 보고하고, 먹이는 대체 텍스처를 쓴다.
- 저장 파일 손상·미래 버전: 경고 후 새 프로필로 시작한다.
- 잘못된 상태 전이: `GameStateMachine`이 거부한다 (중복 종료 방지).
- 시뮬레이션 dt를 1/30초로 상한해 히치 후 터널링을 막는다.
